## Descripción

La tabla `usuarios` gestiona las cuentas del personal que opera el sistema. Las contraseñas se almacenan con **hash Bcrypt** (factor de costo 10) — nunca en texto plano.

**Tabla:** `usuarios`

## Roles disponibles (`RolUsuario`)

| Valor | Descripción |
|-------|-------------|
| `Admin` | Coordinador — acceso total al sistema |
| `Psicologo` | Acceso a formatos F1, F5 y perfil de salud |
| `TrabajoSocial` | Acceso a formato F2 |
| `Guia` | Registro de bitácora e incidencias |

## Endpoints

### `POST /users`
Crea un nuevo usuario del sistema.

**Roles:** `Admin`

```json
{
  "nombre": "María García Ruiz",
  "rol": "Psicologo",
  "nomUsuario": "mgarcia",
  "contrasena": "Segura2026!"
}
```

<Note>
El `nomUsuario` es **único** en la base de datos. Un intento de duplicado retorna `409 Conflict`.
</Note>

---

### `GET /users`
Lista todos los usuarios del sistema.

**Roles:** `Admin`

---

### `GET /users/:id`
Obtiene un usuario por ID.

**Roles:** `Admin`

---

### `PATCH /users/:id`
Actualiza datos del usuario (nombre, rol, estatus).

**Roles:** `Admin`

---

### `PATCH /users/:id/password`
Cambia la contraseña de un usuario. La nueva contraseña se hashea automáticamente.

**Roles:** `Admin`

---

### Usuario inicial (Seed)

Al arrancar la aplicación por primera vez, el sistema crea automáticamente un usuario `Admin` si no existe:

```
nomUsuario: admin
contrasena: Admin1234  (o el valor de SEED_ADMIN_PASSWORD en .env)
```

<Warning>
Cambia la contraseña del admin en el primer inicio de sesión en producción.
</Warning>
