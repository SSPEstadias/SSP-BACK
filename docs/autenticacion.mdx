## Login

<CodeGroup>
```http Petición
POST /auth/login
```
</CodeGroup>

**Cuerpo:**

```json
{
  "nomUsuario": "admin",
  "contrasena": "Admin1234"
}
```

**Respuesta exitosa `200`:**

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

**Errores posibles:**

| Código | Descripción |
|--------|-------------|
| `401`  | Credenciales inválidas |
| `400`  | Campos faltantes o mal formateados |

---

## Uso del token

Incluye el token en el header `Authorization` de **cada petición protegida**:

```http
Authorization: Bearer <access_token>
```

<Warning>
Si no incluyes el header `Authorization`, todos los endpoints protegidos retornarán `401 Unauthorized`.
</Warning>

## Roles del sistema

Cada usuario tiene un rol asignado que determina a qué endpoints puede acceder.

| Rol | Descripción | Acceso principal |
|-----|-------------|-----------------|
| `Admin` | Acceso total | Alta de expedientes, generación de Oficio de Conclusión, gestión de usuarios |
| `Psicologo` | Datos clínicos | F1 (Entrevista), F5 (Notas de Evolución), perfil de Salud |
| `TrabajoSocial` | Datos socioeconómicos | F2 (Estudio Socioeconómico) |
| `Guia` | Operatividad de campo | Bitácora de asistencias, registro de incidencias |

<Note>
El rol `Guia` **no tiene acceso** a los formatos F1 ni F5. Esto garantiza la confidencialidad clínica según el principio de Mínimo Privilegio (RNF-002).
</Note>

## Expiración del token

El token expira en **8 horas** — equivalente a la jornada laboral estándar de los operadores.

Esto es configurable mediante la variable de entorno `JWT_EXPIRES_IN` en el archivo `.env`.

```env
JWT_EXPIRES_IN=8h
JWT_SECRET=tu_secreto_seguro
```

Al expirar, el cliente recibirá un `401 Unauthorized` y deberá hacer login nuevamente.
