## 3. Flujo cívico completo (happy path)

Sigue este orden para verificar el flujo estándar de un beneficiario:

| Paso | Acción | Resultado esperado |
|------|--------|-------------------|
| 3.1 | `POST /shared/beneficiarios` | `201` — beneficiario creado |
| 3.2 | `POST /civico/expedientes` | `201` — expediente con `estatusProceso: INDUCCION` |
| 3.3 | `POST /civico/f1` | `201` — entrevista en `PENDIENTE` |
| 3.4 | `PATCH /civico/f1/:id/estatus` `{ "estatus": "COMPLETADO" }` | `200` — F1 en `COMPLETADO` |
| 3.5 | `POST /civico/f2` | `201` — estudio en `PENDIENTE` |
| 3.6 | `PATCH /civico/f2/:id/estatus` `{ "estatus": "COMPLETADO" }` | `200` — F2 en `COMPLETADO` |
| 3.7 | `GET /civico/f2/expediente/:id/candado-f3` | `{ "habilitado": true }` |
| 3.8 | `POST /civico/f3` | `201` — plan creado |
| 3.9 | `POST /civico/bitacora` con `"asistencia": "PRESENTE"` | `201` — horas suman en expediente |
| 3.10 | `GET /civico/expedientes/:id` | `avanceHoras` incrementado |

## 4. Candado F1+F2→F3 (RF-008)

| # | Verificación | Resultado esperado |
|---|---|---|
| 4.1 | Intentar `POST /civico/f3` sin F1 creado | `403 Forbidden` + mensaje |
| 4.2 | Intentar `POST /civico/f3` con F1 en `EN_PROCESO` (no `COMPLETADO`) | `403 Forbidden` |
| 4.3 | Intentar `POST /civico/f3` con F1 `COMPLETADO` pero F2 `PENDIENTE` | `403 Forbidden` |
| 4.4 | Con F1 y F2 en `COMPLETADO` → `POST /civico/f3` | `201 Created` ✅ |
| 4.5 | `POST /civico/f3` por segunda vez mismo expediente | `409 Conflict` |

## 5. Lógica de 3 strikes — Incidencias (RF-013)

| # | Verificación | Resultado esperado |
|---|---|---|
| 5.1 | `POST /civico/incidencias` 1ª falta acumulativa | `201` — estatus expediente sin cambio |
| 5.2 | `POST /civico/incidencias` 2ª falta acumulativa | `201` — estatus expediente sin cambio |
| 5.3 | `POST /civico/incidencias` 3ª falta acumulativa | `201` — `estatusProceso` → `BAJA_POR_ACUMULACION_DE_INCIDENCIAS` |
| 5.4 | `INASISTENCIA_JUSTIFICADA`, `VISITA_DOMICILIARIA`, `CONVERSATORIO` | No incrementan contador de strikes |

## 7. Integración con Google Drive

| # | Verificación | Resultado esperado |
|---|---|---|
| 7.1 | Variables de Drive **no** configuradas | Servidor arranca con aviso en log; PDFs se siguen generando localmente |
| 7.2 | Variables de Drive **sí** configuradas | Logs muestran `Google Drive Service (OAuth2) inicializado con éxito` |
| 7.3 | Generar un documento con Drive activo | `GET /civico/documentos/historial/:id` muestra `driveFileId` y URL de Drive |
| 7.4 | Generar el mismo documento dos veces (mismo `folioOficio`) | El archivo en Drive se **actualiza** (no duplica) |
