## Descripción

La tabla `beneficiarios` es el punto de entrada único del sistema. **Todo expediente cívico o penal nace de un beneficiario**. Este módulo es parte del `SharedModule` y es consumido por ambos módulos.

**Tabla:** `beneficiarios` — **PK:** `id` (integer, autogenerado)  
**Archivo:** `src/shared/beneficiarios/beneficiario.entity.ts`

<Note>
El `beneficiarioId` es el **primer dato que se necesita** antes de crear un expediente cívico. El flujo correcto es: `POST /beneficiarios` → `POST /civico/expedientes`.
</Note>

---

## Campos de la entidad

| Campo | Tipo DB | Descripción |
|-------|---------|-------------|
| `id` | int (autoincrement) | PK — se usa como `beneficiarioId` en los expedientes |
| `nombre` | varchar(150) | Nombre completo del ciudadano |
| `fechaIngreso` | date | Fecha de ingreso al programa (default: hoy) |
| `tiempoAsignado` | int | Duración de la sanción (número) |
| `unidadTiempo` | enum | `HORAS` para Cívico / `MESES` para Penal |
| `creadoEn` | timestamp | Fecha de creación automática |

## Unidad de tiempo (`UnidadTiempoEnum`)

| Valor | Módulo |
|-------|--------|
| `HORAS` | Justicia Cívica |
| `MESES` | Penal |

## Endpoints

### `POST /beneficiarios`

Registra un nuevo ciudadano. Este registro es el **paso previo obligatorio** para crear un expediente cívico.

<CodeGroup>
```bash cURL
curl -X POST http://localhost:3000/beneficiarios \
  -H "Content-Type: application/json" \
  -d '{
    "nombre": "Juan Carlos Pérez López",
    "tiempoAsignado": 80,
    "unidadTiempo": "HORAS"
  }'
```
</CodeGroup>

**Respuesta `201 Created`:**
```json
{
  "id": 12,
  "nombre": "Juan Carlos Pérez López",
  "fechaIngreso": "2026-03-10",
  "tiempoAsignado": 80,
  "unidadTiempo": "HORAS",
  "creadoEn": "2026-03-10T10:00:00.000Z"
}
```

<Warning>
Guarda el `id` retornado — lo necesitarás como `beneficiarioId` al crear el expediente en `POST /civico/expedientes`.
</Warning>

---

### `GET /beneficiarios`

Lista todos los beneficiarios del sistema ordenados por `creadoEn` descendente.

**Respuesta `200 OK`:**
```json
[
  {
    "id": 12,
    "nombre": "Juan Carlos Pérez López",
    "fechaIngreso": "2026-03-10",
    "tiempoAsignado": 80,
    "unidadTiempo": "HORAS"
  },
  {
    "id": 11,
    "nombre": "María Sánchez Ruiz",
    "fechaIngreso": "2026-03-05",
    "tiempoAsignado": 6,
    "unidadTiempo": "MESES"
  }
]
```

---

### `GET /beneficiarios/filtrar?unidad=HORAS`

Filtra beneficiarios por módulo usando el query param `unidad`.

```http
GET /beneficiarios/filtrar?unidad=HORAS
GET /beneficiarios/filtrar?unidad=MESES
```

**Respuesta `200 OK`:** (solo beneficiarios del módulo Cívico)
```json
[
  {
    "id": 12,
    "nombre": "Juan Carlos Pérez López",
    "tiempoAsignado": 80,
    "unidadTiempo": "HORAS"
  }
]
```

---

### `GET /beneficiarios/:id`

Obtiene un beneficiario por su ID entero.

```http
GET /beneficiarios/12
```

**Respuesta `404` si no existe:**
```json
{
  "statusCode": 404,
  "message": "Beneficiario con id 12 no encontrado",
  "error": "Not Found"
}
```

---

### `PATCH /beneficiarios/:id`

Actualización parcial. Útil para corregir el nombre o el tiempo asignado.

```json
{
  "tiempoAsignado": 100
}
```

---

### `DELETE /beneficiarios/:id`

Elimina un beneficiario.

<Warning>
Si el beneficiario tiene expedientes relacionados (cívicos o penales), la eliminación fallará con `409 Conflict` por la restricción `ON DELETE RESTRICT` de la FK.
</Warning>
