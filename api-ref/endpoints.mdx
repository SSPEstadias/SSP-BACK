## 🔐 Autenticación y Usuarios

### `POST /auth/login`
**Propósito**: Obtener el Bearer Token para todas las peticiones.
- **Request Body**:
  ```json
  {
    "username": "usuario_ejemplo",
    "password": "password123"
  }
  ```
- **Response**: `201 Created` con `{ "access_token": "..." }`.

### `GET /users`
**Propósito**: Gestión del personal (Psicólogos, Trabajo Social, Guías, Admin).

## 👥 Beneficiarios (Shared)
La base de todas las personas registradas en el sistema.

### `POST /beneficiarios`
**Campos Críticos**:
- `nombre` (string): Nombre completo.
- `tiempoAsignado` (number): Basado en su sentencia.
- `unidadTiempo` (Enum): `HORAS` o `MESES`.

---

## 📁 Expediente Cívico (El Corazón del Sistema)

### `POST /civico/expedientes`
Este endpoint crea el vínculo legal. Es un DTO extenso.

**Campos Destacados**:
- `beneficiarioId` (number): ID retornado por `/beneficiarios`.
- `curp` (string(18)): Identidad única.
- `folioExpediente` (string): Identificador interno (ej: "EXP-2025-001").
- `causaPenal` (string): Referencia legal.
- `horasSentencia` (number): Total de horas a cumplir.
- `contactosFamiliares` (jsonb): Objeto con datos de contacto.
- `diasAsignadosJuzgado` (string[]): Ej: `["2025-05-10", "2025-05-11"]`.

## 📅 Operaciones en Campo (Bitácora e Incidencias)

### Bitácora (Asistencia Diaria)
**Endpoint**: `POST /civico/bitacora`
```json
{
  "expedienteId": "UUID-HERE",
  "guiaId": 3,
  "actividadId": 10,
  "fechaActividad": "2025-04-10",
  "horasCubiertas": 4.5,
  "asistencia": "PRESENTE",
  "observaciones": "Llegó puntual y participó activamente."
}
```
> [!IMPORTANT]
> **Regla RF-011**: El sistema rechazará cualquier registro con `horasCubiertas > 8`.

### Incidencias (Control de Strikes)
**Endpoint**: `POST /civico/incidencias`
```json
{
  "expedienteId": "UUID-HERE",
  "guiaId": 3,
  "tipo": "FALTA_INJUSTIFICADA",
  "fechaIncidencia": "2025-04-12",
  "descripcionHechos": "No se presentó a la actividad sin previo aviso.",
  "esAcumulativa": true
}
```
> [!CAUTION]
> Si `esAcumulativa: true` y el conteo llega a **3 strikes**, el sistema cambiará el estatus del expediente a `BAJA_POR_ACUMULACION_DE_INCIDENCIAS` automáticamente.

## 📄 Generación de Documentos (Modelo Híbrido)

### 1. Previsualización (GET)
Endpoints como `GET /civico/documentos/oficio-incorporacion/:id` retornan un **Stream de PDF** para ver o imprimir. **No guarda nada en Drive**.

### 2. Registro y Sincronización (POST)
Endpoints como `POST /civico/documentos/lista-asistencia` realizan:
1. Generan el PDF.
2. Lo suben a la carpeta del beneficiario en **Google Drive**.
3. Registran el `driveFileId` en la tabla `oficios_generados`.

### 3. Paquete Federal (Enlaces Consolidados)
**Endpoint**: `GET /civico/documentos/expediente/:id/paquete-forms`

## 🚨 Manejo de Errores y Validaciones

| Código | Razón | Solución para el Front |
| :--- | :--- | :--- |
| `400 Bad Request` | Faltan campos obligatorios o formato inválido. | Revisa el `message` de la respuesta (usamos `class-validator`). |
| `401 Unauthorized` | Token ausente o expirado. | Re-dirigir al `/login`. |
| `403 Forbidden` | El usuario no tiene rol para esta acción. | Ocultar botones según `user.roles`. |
| `404 Not Found` | El ID (UUID o numérico) no existe en BD. | Verificar que el UUID en la ruta sea correcto. |
| `500 Server Error` | Error crítico (ej: Drive API caída). | Notificar al usuario que intente más tarde. |

## 💡 Guía para Compañeros de Backend

### Estructura del CivicoGoogleDriveService
Si necesitas subir archivos desde un nuevo módulo (ej. Penal), inyecta el servicio y usa:
- `getOrCreateFolder(nombre)`: Crea carpeta raíz si no existe.
- `uploadFile(buffer, nombre, parentId)`: Sube el PDF a la carpeta especificada.

### Validaciones Prohibidas (Check Constraints)
- **Horas Diarias**: BD no acepta > 8 horas por registro en la bitácora.
- **Folios**: Los folios de oficios deben seguir el patrón `SSyPC/SPRS/DGPDyPC/XXXX/YYYY`.
